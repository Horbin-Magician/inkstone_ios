# 性能优化验证 · 2026-11-08

本次保持 Markdown 文件格式、中文及本地化子串搜索语义、外部修改冲突保护和桌面同步协议。没有引入搜索数据库，也没有按文件时间戳跳过同步内容校验。

## 本机基准

环境：当前开发 Mac，Swift release 构建；富文本模型使用 Node.js。测试全部使用临时库，不读取真实笔记。数字是合成数据上的一次测量，不代表真机端到端延迟、内存峰值或耗电。

| 场景 | 原实现 | 优化后 | 测量范围 |
| --- | ---: | ---: | --- |
| 千篇库，30 次保存后快照更新 | 130.37 ms | 1.73 ms | 不含文件写入、正文解析；完整索引重建改为更新当前笔记引用，避免全列表重排 |
| 千个已编辑段落，继续修改一段 | 中位 2.29 ms | 中位 0.114 ms | 50 次 Markdown 序列化；缓存不可变块，换行边界只检查末尾字符 |
| 千条历史中查询某笔记的 10 条记录 | 18.62 ms/次 | 0.705 ms/次 | 10 次查询均值；原全文读取与摘要目录在同次运行中对比；不含首次旧记录建索引 |
| 万篇库，容易命中的多关键词查询 | 34 ms | 50 ms | 3 次均值；并发调度增加开销 |
| 万篇库，无匹配查询 | 572 ms | 150 ms | 3 次均值；最多四个后台工作任务 |
| 万篇库，命中正文末尾 | 573 ms | 157 ms | 3 次均值；保留 Foundation 本地化匹配规则 |

完整扫描千篇库约 0.71 秒，与优化前约 0.70 秒相近：仍读取文件以识别保持时间戳的外部修改。保存流程已经不再触发这种完整扫描。万篇搜索测试每篇包含 100 次重复的中英文短句，另有位于末尾的查询目标；包含容易命中、未命中和末尾命中，避免只测最佳情形。

## 资源使用与行为变化

- 自动保存后的列表只调整当前笔记位置；已有路径只更新该笔记的出链和相关反链。新增路径仍完整重建索引，防止遗漏缺失链接转为有效、同名歧义等变化。
- 同一编辑会话的历史以 60 秒窗口保留起始正文；最新正文仍按自动保存流程写入文件。历史摘要按笔记分目录持久化，全文只在预览版本时加载。旧记录首次使用需建立摘要；摘要损坏时从原文重建，原始恢复文件不会删除。
- 富文本以约 50 ms 合并内容通知，保存/切换前立即读取最新编辑事务；不可变段落使用弱引用缓存，切换文档后可回收。修复了 CRLF 段落重排时将单个 CRLF 误判成空行的问题。
- 搜索最多四路并发，对每篇笔记检查取消；结果按修改时间和路径排序。仍有 200 ms 输入防抖。容易命中的查询有少量调度成本，换取长扫描时的更低延迟；没有改变中文、重音、全角字符等匹配行为。
- 同步连续无变化时，空闲检查间隔依次为 2/4/8/10 分钟；本地修改、回到前台重置，失败退避和 30 秒最短尝试间隔不变。仅路径变化也算有效活动。取舍是前台空闲很久时，远端修改可能最多等待约 10 分钟才被轮询发现；手动同步可立即检查。
- 同步哈希与 ZIP 生成采用 256 KiB 读取块。ZIP 输出先写临时文件，最后在支持时以内存映射交给 FileDocument；系统导出仍可能自行分配内存。备份内容、大小上限及空文件夹支持不变。
- 阅读器后台生成适合显示尺寸的图片；富文本大幅静态图片使用最长边 1920 px 的 PNG 显示副本。小图和动画保留原格式，笔记库原始附件不变。测试确认 2400×1200 图片生成 640×320 缩略图。
- 批量移动、删除只在整批结束时刷新一次，部分失败仍会刷新已完成结果。

| 阶段 | 优化前 | 优化后 |

初次扫描原本的 655 ms 中，路径检查约 160 ms，协调读取约 480 ms，后者包含约 45 ms 的哈希读取与计算。瓶颈主要是协调访问的重复准备，而不是 SHA-256 算法。使用 `NSFileCoordinator.prepare` 为扫描和本地暂存准备读取批次，并复用批次协调器，扫描中的协调读取降至约 88 ms。对一个文件做暂存时，批次准备有约 2 ms 的额外成本，整体收益主要来自两次全库扫描。

实现遵循 [Apple 批量文件协调接口说明](https://developer.apple.com/documentation/foundation/nsfilecoordinator/prepare%28forreadingitemsat%3Aoptions%3Awritingitemsat%3Aoptions%3Aerror%3Abyaccessor%3A%29)：批次声明根目录，批次内仍逐文件调用协调读取；使用默认读取选项让文件呈现器保存未落盘内容。批次完成回调通过 `defer` 保证在读取失败时也调用。批次只包含同步本地读取，不跨越网络请求。未保留试验过的并发扫描方案。

安全边界保持：每次扫描读取全部文件并计算内容哈希；发布前再次校验全库；暂存、上传和下载继续验证摘要；保留强 ETag 条件发布、发布后的 pending 提交恢复、覆盖前比较、备份与原子写入。没有依据时间戳跳过哈希，没有扩大网络并发度或修改磁盘协议。

新增回归覆盖文件呈现器保存未落盘正文、传输期间同大小且保留时间戳的外部修改、发布前取消、符号链接、超限附件，以及失败后的重试。既有冲突副本、损坏下载、过期发布、清单丢失/代次回退和已确认发布后的中断恢复测试继续通过。真实 Rust 桌面核心与一次性本地 HTTP WebDAV 的笔记、附件、移动、冲突和删除互通通过；iOS Simulator 构建通过。真实 iCloud/第三方文件提供商、真机耗电和网络吞吐仍需设备验收。

单篇修改场景中，首次扫描的路径处理从 136.86 ms 降至 24.77 ms，首次扫描整体从 244.04 ms 降至 129.20 ms；发布前再次扫描从 227.72 ms 降至 121.37 ms；本地暂存从 4.03 ms 降至 1.93 ms。

具体变化：

- 路径检查只需文件类型，改用逐级 `lstat`，省去每级路径完整 Foundation 属性字典的构造，并只在末尾生成 URL。每次访问仍检查实际文件系统，没有缓存检查结果；符号链接仍拒绝，只有 `ENOENT` 允许继续以支持新文件／新目录，其余检查错误直接返回。
- 同步扫描从枚举 URL 的标准化路径提取相对路径，先校验根目录前缀，再执行逐级检查；移除重复的符号链接解析。禁止字符集合只构造一次，路径语法与字节长度限制保持原样。
- 暂存先验证缓存对象摘要，再按真正需要读取的本地文件数量选择协调方式：多文件使用批次，一个文件使用普通逐文件协调，没有本地读取则不准备批次。纯下载和已验证缓存对象无需触发本地读取批次。

83 项常规回归通过。新增测试覆盖 Unicode/百分号路径跨设备往返、路径字节上限和控制字符限制、损坏暂存重新校验、同步期间父目录被替换为符号链接、非目录父路径检查失败；既有文件呈现器保存、外部修改、取消、中断恢复和冲突保护回归继续通过。本地 HTTP WebDAV 与 Rust 桌面核心互通通过。完整哈希、发布前全库复核和条件发布均保留。

## 第三阶段：到期时间驱动的同步调度

`AutoSyncSchedule.dueDate` 统一合并防抖、失败退避及最小同步间隔；独立 `AutoSyncScheduler` 只管理一次可取消的等待，网络同步和文件提交仍由原有流程管理。前后台、编辑器／设置暂停、配置、加载和本地写入状态变化会重新调度；进入后台撤销尚未开始的等待。回调开始前释放计时任务，避免同步状态变化误取消正在运行的事务。等待函数可注入，测试用可控时钟验证旧回调失效、暂停恢复及重复调度不创建新等待。

## 第三阶段：文件附件传输与字节预算

远端接口改为 URL 文件输入／输出。WebDAV 下载使用有大小限制的下载任务，上传使用文件输入流；上传响应仍写入临时文件并限制大小。暂存、备份和安装使用经过完整哈希校验的文件复制，公开目标不覆盖并发新建文件。哈希逐块读取 256 KiB，并在每块后释放 Foundation 临时对象。发布后的提交校验不响应取消，恢复日志屏障保留。

传输同时受 3 个任务和 256 MiB 在途字节预算限制。旧清单没有文件大小，下载按 128 MiB 单文件上限预留（最多两个未知大小下载并发）；上传按实际文件大小预留。预算不是整个应用进程的内存上限，也不是恢复目录总磁盘上限。

| 下载及安装阶段 | 322.28 ms | 360.38 ms |

## 第三阶段：富文本版本通知与快照屏障

输入事件只发送 revision／组合输入状态；保存、导航、模式切换和导出显式取得完整快照。多个同时发生的快照请求合并。导航／模式切换的快照在 WebKit 内冻结后续输入，失败则恢复编辑，成功保持冻结直到旧视图拆除或新文档加载，避免快照返回后又输入的字符被切换操作丢弃；冻结不会打断正在进行的组合输入。

为保证这条路径的正确性，提前抽取第四阶段所需的 `EditorSession`：统一编辑与快照版本、组合输入、保存阶段／失败、导航判断和历史会话身份。快照失败明确返回失败；WebKit 进程中断不会把旧正文当成保存成功。用户可以明确选择最近快照转到源码核对，旧 WebKit 消息在更换会话身份后失效。

同机 Playwright WebKit、390×844 视口、相同笔记及 10 次输入（80 ms 间隔）：

| 数据集 | 原输入消息字节 | 新输入消息字节 | 原／新输入到下一帧 p50 | 原／新 p95 |
| --- | ---: | ---: | ---: | ---: |
| 约 32 KiB | 325,016 | 761 | 17 / 17 ms | 38 / 40 ms |
| 接近 8 MiB | 84,061,036 | 781 | 17 / 17 ms | 26 / 33 ms |

本轮证明桥接正文流量消除，未证明输入延迟改善（p95 有波动甚至变慢）；这些是桌面 WebKit 模拟移动视口的测量，不是 iPhone 中文输入法结果。保存时仍有一次完整快照传输。测试确认最终快照包含全部 10 次输入。原始日志 `.build/performance/stage3/bridge-before.log`、`bridge-after.log`；`INKSTONE_BRIDGE_BENCHMARK=1 npm run test:browser --prefix RichEditor -- --workers=1 bridge-benchmark.spec.js` 可复测。

新增验证包括版本通知不带正文、视图重建后的版本连续性、过期快照、保存期间继续输入、组合输入与快照交错、快照失败禁止导航、导航冻结／恢复。WebKit 回归 15 项通过（性能用例默认跳过），Swift 全量 111 项通过；iOS 模拟器 Release 构建通过。真机拼音／手写、即时返回及进程切换仍需设备验收。

## 第三阶段：统一图片预览与缓存范围

阅读器和富文本中的远程图片统一经过原生预览管线；下载最多 32 MiB，原图单边最多 20,000 像素且总计不超过 1 亿像素，缩略图最大边长 1920。加载与解码合计最多 3 个任务；缓存按解码像素与编码数据合计限制为 64 MiB／128 项。视图仍可能持有已逐出的图片，这个缓存预算不是整个进程的内存上限。

缓存键包含库地址、笔记路径、附件来源、刷新代次和预览尺寸。切换笔记／笔记库或刷新外部修改会更新 WebKit 图片地址并取消旧任务；正文自动保存不会反复刷新图片。符合像素／帧数限制的小 GIF 在富文本中保留动画，较大动画显示首帧预览；附件原文件不修改。远程图片只支持 HTTP(S)，拒绝 URL 内嵌账号密码。没有引入持久化图片缓存。

同机 Release、同一份 6000×4000 PNG，保留 6 张独立解码结果；基线与优化分别在独立测试进程运行，夹具提前生成：

| 指标 | 整图解码参考基线 | 统一缩略图管线 |
| --- | ---: | ---: |
| 耗时 | 147.54 ms | 152.85 ms |
| 测试进程峰值 RSS | 619,020,288 B | 272,613,376 B |
| 保留的解码像素内存 | 576,000,000 B | 58,982,400 B |

这是整图解码与缩略图组件的对比，不是原应用 AsyncImage 或真机端到端测量；内存下降约 56%，耗时略增，未声称输入延迟改善。生成的图片是高压缩率合成 PNG，真实照片和 WebKit 进程内存还需真机测试。原始日志在 `.build/performance/stage3/images-before.log`、`images-after.log`。复现设置 `INKSTONE_IMAGE_BENCHMARK=1` 和 `INKSTONE_IMAGE_FIXTURE_PATH`，依次单独运行 Release 的 `prepareLargeImageFixture`、`imageDecodeBaseline`、`imageDecodeThumbnails`。

回归覆盖库／路径／来源／代次缓存隔离、并发上限、取消、像素与字节超限，以及 WebKit 远程图片地址范围更新。本地真实 HTTP 服务验证缩略图下载和 33 MiB 响应拒绝；Swift／Rust WebDAV 互操作仍通过。该测试另外复现了同一文件 URL 改写后缓存旧文件大小导致上传截短的问题，已先补失败回归并独立修复：传输前清除 URL 元数据缓存。

全库正文按需加载与持久化搜索索引仍留在后续决策点；当前结果没有提供足够真机证据支持引入数据库。真实设备上的输入延迟、完整应用内存／磁盘占用和网络同步吞吐仍待第四阶段验收。

最终校验：Swift 共发现 118 项，104 项通过、14 项默认跳过（按需性能／HTTP 用例）；另行启用的 3 项 HTTP 测试通过。模型测试 24 项通过，WebKit 16 项通过／1 项性能用例跳过，iOS 模拟器 Release 构建成功，工程连续生成三次字节一致。图片资源重建已包含在提交中。

## 阅读与富文本加载优化 · 2026-11-09

- 阅读正文显示后延迟 350 ms 预热 WebView 页面；仅加载编辑器外壳，进入编辑时才解析正文。离开页面会取消尚未开始的预热。
- 阅读/富文本切换保留一个编辑器实例、选择位置和撤销历史；隐藏时禁用编辑、焦点、点击和辅助功能访问。再次进入时解除快照冻结，按需同步阅读期间修改的正文。切换笔记仍按文档 ID 重置编辑状态；源码模式仍销毁富文本实例。
- 同步配置合并为一次 JavaScript 桥接调用，标题补全选项延迟到链接对话框打开时创建；Markdown 源码范围和 ProseMirror 文档共享同一轮分词结果，消除重复全文分词。
- 代价：阅读期间保留一个 WebView 及已加载文档，占用额外内存；首次进入仍需构建正文 DOM。超长笔记的首次布局和真机键盘动画尚未单独测量。

本机 WebKit 合成基准：300 个标题/段落、22,990 字节，预热一轮后测量 10 轮；完整文档初始化与强制布局中位数 11 ms，保留实例后的恢复编辑与强制布局中位数 1 ms。该比较只覆盖网页内的两条代码路径，不含 WKWebView 创建、原生桥接、SwiftUI 和系统键盘，不能当作真机端到端耗时。

验证：24 项模型测试、WebKit 交互回归（包含冻结恢复、撤销、延迟补全、预热后加载和阅读期间正文变化）、123 项 Swift 测试及 iOS Simulator Debug 构建通过。基准可用 `INKSTONE_LOAD_BENCHMARK=1 npm --prefix RichEditor run test:browser -- --grep 'document initialization versus'` 重复执行。

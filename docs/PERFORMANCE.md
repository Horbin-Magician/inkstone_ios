# 性能优化验证 · 2026-11-08

本次保持 Markdown 文件格式、中文及本地化子串搜索语义、外部修改冲突保护和桌面同步协议。没有引入搜索数据库，也没有按文件时间戳跳过同步内容校验。

## 本机基准

环境：当前开发 Mac，Swift release 构建；富文本模型使用 Node.js。测试全部使用临时库，不读取真实笔记。数字是合成数据上的一次测量，不代表真机端到端延迟、内存峰值或耗电。

| 场景 | 原实现 | 优化后 | 测量范围 |
| --- | ---: | ---: | --- |
| 千篇库，30 次保存后快照更新 | 130.37 ms | 1.73 ms | 不含文件写入、正文解析；完整索引重建改为更新当前笔记引用，避免全列表重排 |
| 千个已编辑段落，继续修改一段 | 中位 2.29 ms | 中位 0.114 ms | 50 次 Markdown 序列化；缓存不可变块，换行边界只检查末尾字符 |
| 千条历史中查询某笔记的 10 条记录 | 18.62 ms/次 | 0.705 ms/次 | 10 次查询均值；原全文读取与摘要目录在同次运行中对比；不含首次旧记录建索引 |
| 万篇库，容易命中的多关键词查询 | 34 ms | 50 ms | 3 次均值；并发调度增加开销 |
| 万篇库，无匹配查询 | 572 ms | 150 ms | 3 次均值；最多四个后台工作任务 |
| 万篇库，命中正文末尾 | 573 ms | 157 ms | 3 次均值；保留 Foundation 本地化匹配规则 |

完整扫描千篇库约 0.71 秒，与优化前约 0.70 秒相近：仍读取文件以识别保持时间戳的外部修改。保存流程已经不再触发这种完整扫描。万篇搜索测试每篇包含 100 次重复的中英文短句，另有位于末尾的查询目标；包含容易命中、未命中和末尾命中，避免只测最佳情形。

## 资源使用与行为变化

- 自动保存后的列表只调整当前笔记位置；已有路径只更新该笔记的出链和相关反链。新增路径仍完整重建索引，防止遗漏缺失链接转为有效、同名歧义等变化。
- 同一编辑会话的历史以 60 秒窗口保留起始正文；最新正文仍按自动保存流程写入文件。历史摘要按笔记分目录持久化，全文只在预览版本时加载。旧记录首次使用需建立摘要；摘要损坏时从原文重建，原始恢复文件不会删除。
- 富文本以约 50 ms 合并内容通知，保存/切换前立即读取最新编辑事务；不可变段落使用弱引用缓存，切换文档后可回收。修复了 CRLF 段落重排时将单个 CRLF 误判成空行的问题。
- 搜索最多四路并发，对每篇笔记检查取消；结果按修改时间和路径排序。仍有 200 ms 输入防抖。容易命中的查询有少量调度成本，换取长扫描时的更低延迟；没有改变中文、重音、全角字符等匹配行为。
- 同步连续无变化时，空闲检查间隔依次为 2/4/8/10 分钟；本地修改、回到前台重置，失败退避和 30 秒最短尝试间隔不变。仅路径变化也算有效活动。取舍是前台空闲很久时，远端修改可能最多等待约 10 分钟才被轮询发现；手动同步可立即检查。
- 同步哈希与 ZIP 生成采用 256 KiB 读取块。ZIP 输出先写临时文件，最后在支持时以内存映射交给 FileDocument；系统导出仍可能自行分配内存。备份内容、大小上限及空文件夹支持不变。
- 阅读器后台生成适合显示尺寸的图片；富文本大幅静态图片使用最长边 1920 px 的 PNG 显示副本。小图和动画保留原格式，笔记库原始附件不变。测试确认 2400×1200 图片生成 640×320 缩略图。
- 批量移动、删除只在整批结束时刷新一次，部分失败仍会刷新已完成结果。

## 同步分阶段测量与优化（续）

本节使用本机 **macOS Debug** 构建，与前面的 Release 基准分开比较。临时库含 20 个目录、1000 篇不同内容的笔记，每篇约 3 KB；另测 32 MiB 二进制附件。远端使用 `MemoryRemote` 排除网络波动，因此下表测量本地同步流水线开销，不代表实际 WebDAV 服务商速度。优化前为一次细分计时，优化后为三次独立运行的中位数；文件缓存、设备负载和文件提供商均会影响结果。

| 场景 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 首次同步 1000 篇 | 2.090 s | 0.955 s | 54% |
| 1000 篇无变化 | 0.775 s | 0.255 s | 67% |
| 千篇库修改一篇 | 1.337 s | 0.510 s | 62% |
| 千篇库下载 100 篇修改 | 1.507 s | 0.709 s | 53% |
| 千篇库新增 32 MiB 附件 | 1.388 s | 0.585 s | 58% |
| 含附件的库无变化 | 0.689 s | 0.287 s | 58% |

单篇修改的阶段明细（毫秒；各阶段中位数不一定加总为总耗时中位数）：

| 阶段 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 恢复检查、读取基线 | 7.63 | 7.41 |
| 首次全库扫描 | 655.24 | 235.90 |
| 获取清单（模拟远端） | 0.007 | 0.007 |
| 清单校验与合并 | 14.40 | 14.83 |
| 规划与本地暂存 | 2.11 | 4.35 |
| 下载（此场景无下载） | 0.011 | 0.011 |
| 远端准备（模拟） | 0.001 | 0.001 |
| 上传（模拟） | 0.119 | 0.120 |
| 发布前再次扫描校验 | 653.68 | 243.26 |
| 发布清单（模拟） | 0.009 | 0.006 |
| 本地提交、基线与清理 | 4.03 | 4.29 |

初次扫描原本的 655 ms 中，路径检查约 160 ms，协调读取约 480 ms，后者包含约 45 ms 的哈希读取与计算。瓶颈主要是协调访问的重复准备，而不是 SHA-256 算法。使用 `NSFileCoordinator.prepare` 为扫描和本地暂存准备读取批次，并复用批次协调器，扫描中的协调读取降至约 88 ms。对一个文件做暂存时，批次准备有约 2 ms 的额外成本，整体收益主要来自两次全库扫描。

实现遵循 [Apple 批量文件协调接口说明](https://developer.apple.com/documentation/foundation/nsfilecoordinator/prepare%28forreadingitemsat%3Aoptions%3Awritingitemsat%3Aoptions%3Aerror%3Abyaccessor%3A%29)：批次声明根目录，批次内仍逐文件调用协调读取；使用默认读取选项让文件呈现器保存未落盘内容。批次完成回调通过 `defer` 保证在读取失败时也调用。批次只包含同步本地读取，不跨越网络请求。未保留试验过的并发扫描方案。

安全边界保持：每次扫描读取全部文件并计算内容哈希；发布前再次校验全库；暂存、上传和下载继续验证摘要；保留强 ETag 条件发布、发布后的 pending 提交恢复、覆盖前比较、备份与原子写入。没有依据时间戳跳过哈希，没有扩大网络并发度或修改磁盘协议。

新增回归覆盖文件呈现器保存未落盘正文、传输期间同大小且保留时间戳的外部修改、发布前取消、符号链接、超限附件，以及失败后的重试。既有冲突副本、损坏下载、过期发布、清单丢失/代次回退和已确认发布后的中断恢复测试继续通过。真实 Rust 桌面核心与一次性本地 HTTP WebDAV 的笔记、附件、移动、冲突和删除互通通过；iOS Simulator 构建通过。真实 iCloud/第三方文件提供商、真机耗电和网络吞吐仍需设备验收。

## 路径检查与小批量暂存（第二轮同步优化）

沿用上一节的 macOS Debug、临时千篇库和内存模拟远端。本轮修改前后各独立运行三次，以下均为中位数，比较基线是已经使用批量协调的版本；不能与真实服务商端到端速度等同。

| 场景 | 本轮前 | 本轮后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 首次同步 1000 篇 | 917.61 ms | 603.56 ms | 34% |
| 1000 篇无变化 | 250.53 ms | 147.59 ms | 41% |
| 千篇库修改一篇 | 498.39 ms | 274.74 ms | 45% |
| 千篇库下载 100 篇修改 | 664.81 ms | 459.04 ms | 31% |
| 千篇库新增 32 MiB 附件 | 570.57 ms | 345.39 ms | 39% |
| 含附件的库无变化 | 271.91 ms | 161.64 ms | 41% |

单篇修改场景中，首次扫描的路径处理从 136.86 ms 降至 24.77 ms，首次扫描整体从 244.04 ms 降至 129.20 ms；发布前再次扫描从 227.72 ms 降至 121.37 ms；本地暂存从 4.03 ms 降至 1.93 ms。

具体变化：

- 路径检查只需文件类型，改用逐级 `lstat`，省去每级路径完整 Foundation 属性字典的构造，并只在末尾生成 URL。每次访问仍检查实际文件系统，没有缓存检查结果；符号链接仍拒绝，只有 `ENOENT` 允许继续以支持新文件／新目录，其余检查错误直接返回。
- 同步扫描从枚举 URL 的标准化路径提取相对路径，先校验根目录前缀，再执行逐级检查；移除重复的符号链接解析。禁止字符集合只构造一次，路径语法与字节长度限制保持原样。
- 暂存先验证缓存对象摘要，再按真正需要读取的本地文件数量选择协调方式：多文件使用批次，一个文件使用普通逐文件协调，没有本地读取则不准备批次。纯下载和已验证缓存对象无需触发本地读取批次。

83 项常规回归通过。新增测试覆盖 Unicode/百分号路径跨设备往返、路径字节上限和控制字符限制、损坏暂存重新校验、同步期间父目录被替换为符号链接、非目录父路径检查失败；既有文件呈现器保存、外部修改、取消、中断恢复和冲突保护回归继续通过。本地 HTTP WebDAV 与 Rust 桌面核心互通通过。完整哈希、发布前全库复核和条件发布均保留。

复现命令仍为 `INKSTONE_SYNC_BENCHMARK=1 swift test --filter PerformanceTests.syncStages`。本轮前后原始日志位于本机 `.build/performance/sync-paths-2026-11-08/`。真实文件提供商的 POSIX 路径访问、下载等待和网络吞吐仍需真机验收；本轮没有改动网络并发策略或附件上传方式。
